# Prompt 10: Documentation Prompt

Use after architectural changes.

```markdown
Update the documentation for:
[CHANGE]

Documentation must explain:
- what changed
- why it exists
- architecture
- data flow
- security boundary
- failure behavior
- performance implications
- how to run it
- how to test it
- known limitations

Do not write marketing language.
Prefer diagrams and concrete examples.
Never document behavior that the implementation does not actually provide.
```
